Project Scope (What the project must demonstrate)

You must show at least one substantive use of an ontology beyond simple lookup. Acceptable uses include:
	1.	Hierarchical reasoning
	•	Grouping or differentiating observations using ontology structure
	•	Example: parent vs child phenotype classes
	2.	Controlled terminology
	•	Restricting valid labels for entities or events
	•	Example: enforcing HPO terms instead of free-text phenotypes
	3.	Inference using ontologies (at least one)
	•	Rule-based decision support
	•	Description-logic classification using axioms
	•	Probabilistic or temporal reasoning (optional / advanced)
	•	Ontology-augmented RAG or LLM pipeline (optional)

Domain and data source are flexible, but data access friction matters.

⸻

Deliverables (Final)

1. Oral Presentation (20 minutes)
	•	Present methods and results
	•	Demonstrate ontology use (live or screenshots)
	•	Include multiple presenters if desired
	•	Submit slides

2. Written Essay (4–6 pages, excl. figs & refs)

Structured like an academic paper:
	•	Problem & motivation
	•	Background
	•	Methods (technical, code-level detail)
	•	Results (honest, preliminary acceptable)
	•	Discussion

Required inclusions
	•	Explicit justification for why the ontology was necessary
	•	Programmatic querying of an ontology
	•	LLM usage attestation

Optional:
	•	Separate 2-page technical appendix (reduces main text to 4 pages)

3. Ontology Submission
	•	Link to off-the-shelf ontology or
	•	Upload any custom / modified ontology artifacts

Checkpoint 1 — Project Plan (Ungraded)

Goal: Show the project is feasible and well scoped.

Submit (1–2 pages):
	•	Team members and shared research interest
	•	Knowledge resources (ontologies, terminologies, data)
	•	Clear project goal(s), achievable in ~5 weeks
	•	Planned ontology use (grouping, inference, etc.)
	•	Optional: tools (Python, SPARQL, LLMs, ML)

Feedback focuses on scope realism.

⸻

Checkpoint 2 — Ontology Interaction Demo (Graded, Feb 25)

Goal: Prove you can programmatically use an ontology.

Must include:
	•	Code or API calls querying an ontology (e.g., BioPortal)
	•	Evidence of interaction (screenshots or outputs)
	•	Simple application to data (real or synthetic)
	•	Description of any blockers or issues

Minimum bar:
	•	Successful ontology query + retrieval
	•	Demonstrated use beyond manual browsing

This checkpoint confirms you are “on track.”

⸻

Evaluation Emphasis (Implicit Rubric)

Projects are evaluated on:
	•	Correct and meaningful ontology use
	•	Technical clarity in methods
	•	Appropriate scope
	•	Honest interpretation of results
	•	Clear linkage between ontology and downstream reasoning

Publishable results are not expected.
